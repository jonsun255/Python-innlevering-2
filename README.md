# Python-innlevering-2
A repository for python Tasks

To have a well organised and structured code ownership, with a clear understanding from the development team. You will need good documentation, that explains your commits in a short and concise way, both through comments in the code and the commit messages. By using diagrams, the team will have a easier and more cooperative understanding of the assignement and how to divide the tasks into smaller modules. Some tools may include Use-cases and sequence diagrams, which explains how the operation is structured.
When working with a larger project, there will be a lot of edge cases that may cause problems with the code. By implenting automated test, you can check that every commit into the branch, wont disrupt the program. Although these tests have to be made with each commit.
Whenever there is a new push to the branch, another peer should review the code. This is important, because other people should be able to understand what the code is, and how it connects to the rest of the system.
